# SOL table

Generated by `scripts/sol.py`. Do not hand-edit — it is regenerated from
`machine_model.md` and `dataflow.yaml`, and an edit here is a number with no `method:`.

The shape it produces:

```
graph: sha256:<16 hex>
target: <target>
machine model config: {...}
fabric iterations: 3 (degraded below isolated BW)

| node | unit | regime | compute (ms) | memory (ms) | tax (ms) | SOL (ms) | row |
|---|---|---|---|---|---|---|---|
| capture | vic | memory | 0.000 | 3.200 | 0.041 | 3.261 | units.vic.sustained_bytes |

critical path SOL: 21.400 ms

## Hidden handoffs
- infer -> track is `copy` in the handoff matrix with no node paying for it; 3110400 B
  are missing from every floor above.
```

`regime` is the floor that won, and `row` is the machine-model row that produced it —
the row to re-measure when a stage comes in under its own SOL.

`fabric iterations` above 1 means overlapping demand exceeded §5's knee and every
shared-memory node's bandwidth was degraded until the graph was self-consistent. The
memory floors in that table are therefore larger than the isolated §4 numbers, which
is the point.
