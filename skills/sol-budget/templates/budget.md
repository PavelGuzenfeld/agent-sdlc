# Budget

Generated by `scripts/sol.py`, read by `scripts/budget_check.py`. Do not hand-edit —
to change a budget, add a row to `budget_revisions.md`.

The shape it produces:

```
graph: sha256:<16 hex>
window: 33.300 ms, margin 25%
critical path SOL: 21.400 ms
allowed critical path: 24.975 ms

| node | regime | SOL (ms) | fraction | allowed p99 (ms) |
|---|---|---|---|---|
| capture | memory | 3.261 | 0.70 | 4.659 |
```

`fraction` is how much of SOL the node is allowed to spend — 0.70 memory-bound, 0.50
dispatch-dominated, 0.85 tight compute, or a per-node `fraction:` in `dataflow.yaml`.
`allowed p99` is SOL ÷ fraction, and it is a p99, not a mean: a deadline is missed by
the tail.

`graph` must match the `graph` column in `measurements.csv`. A mismatch means the
measurement was taken against a different dataflow, and `budget_check.py` refuses the
row rather than comparing it to this ceiling.

`regime` ties break toward compute, then memory, then tax — a node whose compute and
memory floors are exactly equal gets the looser 0.85 fraction. Break the tie in the
graph with a per-node `fraction:` if that matters.
